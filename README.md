# Numbat

Numbat is a collection of architectural modelling and analysis tools for Rhino 8. Commands use the `nb` prefix and are intended for small, repeatable production tasks that would otherwise require manual setup or repeated modelling operations.

## Installation

Requires Rhino 8 (8.21 or later) on Windows. Mac is not supported.

Open **Rhino Package Manager**, enable **Include pre-releases**, search for **Numbat**, and install the package.

See [CHANGELOG.md](CHANGELOG.md) for what changed in each release.

## Analysis commands

### nbGFA

Tracks gross floor area live while you model. Model each storey as one closed box, give each box a use (Residential, Office, Retail, ..., or Unassigned while you decide), and a floating window shows the GFA of each use, its share of the total, and the selected volumes. You can limit each use by share (%) or area (m²), and set a target for the total GFA; the window flags anything outside its limits. Uses are tracked either on each object or by a `nbGFA::<use>` sublayer, and are saved in the document. GFA is always reported in m² in metric models.

Volumes are checked as you work: open polysurfaces, bottoms that are slightly tilted, and boxes with no flat bottom are flagged, and `nbGFACheck` also finds overlapping volumes and can level tilted ones.

Everything is done from the window. For macros and keyboard users there are three helper commands; they don't appear in Rhino's autocomplete (so typing `nb` only offers `nbGFA`), but they work when typed in full:

| Command | What it does |
|---|---|
| `nbGFA` | Opens the GFA window, or brings it to the front. |
| `nbGFAAssign` | Select volumes, then pick a use (or Exclude) on the command line. |
| `nbGFACheck` | Checks assigned volumes: open, tilted, no flat bottom, overlapping. |
| `nbGFAHelp` | Shows the how-to guide ([docs/nbGFA.md](docs/nbGFA.md)). |
| `nbGFADemo` | Adds three example blocks (2, 4 and 6 storeys) on an "nbGFA demo" layer to try nbGFA on. |

## Modelling commands

### nbRandomColour

Randomises Rhino layer colours. Colours can be assigned independently to every layer or generated by top-level layer group with lighter nested-layer variations.

### nbTextureShuffle

Breaks up obviously repeating textures (brick, stone, timber cladding). Opens a small window: select surfaces, polysurfaces, meshes or SubDs, then click **Shuffle** as often as you like until it looks right. Each click gives the selected objects a box mapping moved by a new random amount, and each click is one undo step.

- **Repeat X / Y / Z** set how big one texture repeat is. Changing them resizes the selection's box mapping straight away, keeping its position.
- **Align to**: World keeps neighbouring objects continuous; Object follows each object's largest flat face.
- **Same for all selected** moves every selected object's texture by the same amount; off, each gets its own.
- **Up to / Along** limit how far, and in which directions, the texture may move.
- **Straighten** puts the box mapping back at its starting position, with no random move.
- **Remove mapping** takes the box mapping off, so Rhino's default surface mapping is used again.

`-nbTextureShuffle` on the command line (for macros) shuffles the selected objects once with the window's saved settings.

### nbPavementPlacer

Arrays a paving module along selected curves with controls for rows, gaps, rotation, scale variation, side and start-point behaviour.

### nbHandrail

Generates configurable architectural handrails from selected curves. Available construction includes top and bottom rails, posts, vertical or zig-zag infill, framed panels, sheets, end tabs and support feet.

## Commands in rework

nbStair, nbStairStraight, nbStairSpiral and nbPV have been withdrawn from the package for now while they are rebuilt to a more professional standard. They will come back in a later release. nbProgramBlocks and nbTemplate have been retired.

## Building from source

Requires the .NET 8 SDK (or newer) on Windows.

```powershell
dotnet build src/Numbat/Numbat/Numbat.csproj -c Release   # build net48 + net8.0 plug-ins
./scripts/Build-YakPackage.ps1                            # build and package into dist/*.yak
```

To debug, use the `Rhino 8 - netcore` launch profile, or drag `Numbat.rhp` from `bin/` into Rhino. Debug builds also include the commands that are in rework; release builds and the published package do not. Every push and pull request is built by CI, and the resulting `.yak` can be downloaded from the workflow run. Pushing a `v*` tag starts a release. The package first goes to McNeel's test Yak server for a final check, and it is published to Yak and GitHub Releases only after the maintainer approves.
