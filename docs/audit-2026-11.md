# Repository audit, November 2026

> Section 1 was resolved by the repo and pipeline cleanup (`chore/repo-pipeline`). The package is now net48 + net8.0, built by CI on every PR, and released by tag through `release.yml` and `/release`. The remaining work is branch protection (it needs CI on main first) and the 15 MB GIF.

This is a snapshot of the repository at `d6c9ca9` (dev, one commit ahead of main / v0.3.0-beta.2). Use it as a backlog: tick items off or delete them as they are fixed, and record user-visible fixes in `CHANGELOG.md`.

Severity:
- **H** means wrong results or lost work.
- **M** means real but limited impact.
- **L** means polish.

## 1. Packaging and release pipeline

- [x] **H: The Yak package only contains the net7.0 build.** CI builds both net48 and net7.0, but runs `yak build` inside `bin/Release/net7.0`, so net48 is never shipped. (A local `yak build` produced `numbat-…-rh8_0-any.yak` containing only the net7.0 files.) Users running Rhino 8 with `/netfx` cannot load it. Choose one of these:
  - (a) Drop `net48` and target `net7.0` only. This is simplest, and Rhino 8 runs .NET Core by default on Windows and Mac.
  - (b) Stage `net48/` and `net7.0/` subfolders in one package directory with the manifest at the root, the layout McNeel documents for multi-targeted Rhino 8 packages.
- [x] **M: CI never builds anything except tags.** There is no build on push or PR to `dev` or `main`, so a broken build is only discovered at release time. Add a `build.yml` that runs `dotnet build -c Release` on push and pull_request.
- [x] **M: Nothing checks that the tag and the csproj version agree.** CI takes the Yak version from the tag, while the assembly version comes from `<Version>`. `PublishRelease.ps1` keeps them aligned, but a manually pushed tag would not. Add a CI step that fails when `v<Version>` ≠ tag.
- [x] **M: `PublishRelease.ps1` uses `Read-Host`,** which can't be answered from Claude Code's non-interactive shell. Add a `-Yes` switch, keeping the default interactive.
- [x] **M: GitHub Releases stop at v0.1.0-beta.3.** Later tags have no release. Have CI create a GitHub Release from the tag, with notes from the matching `CHANGELOG.md` section and the `.yak` attached.
- [x] **L: Dead steps in the workflow.** It copies the manifest and icon into `net48/`, which is never used. It uses `setup-dotnet 7.0.x`, an out-of-support SDK (8.0.x builds net7.0 fine). It downloads `yak.exe` from `latest`, unpinned.
- [x] **L: The manifest has no `keywords`.** Adding some (`architecture, stairs, handrail, pv, gfa, layers`) helps Package Manager search.
- [ ] **L: `main` has no branch protection.** This is optional for a solo repo, but it stops accidental pushes once CI exists.

## 2. Repository hygiene

- [ ] **L: Line endings and whitespace are inconsistent.** The latest commit mixes tabs and spaces (`NumbatTemplateCommand.cs`), and `LICENSE` has mixed line endings. An `.editorconfig` has been added. Normalise files when they are next touched.
- [x] **L: `launchSettings.json` has a trailing comma.** Visual Studio tolerates it, but strict JSON parsers do not.
- [x] **L: Commit messages** are mostly GitHub-UI defaults (`Update X.cs`). CLAUDE.md now defines Conventional Commits.
- [ ] **L: `assets/demos/nbPavementPlacer.gif` is 15 MB.** It makes the README slow to load and bloats every clone. Re-encode it (fewer frames or smaller dimensions) or host it on a GitHub Release / issue attachment.
- [ ] **L: There are no automated tests.** Two options:
  - Extract pure maths (stair solvers, ProgramBlocks parsing, GFA area logic) so it can be unit-tested without Rhino.
  - Use McNeel's `Rhino.Testing` (NUnit plus Rhino.Inside) for geometry tests.

## 3. Cross-cutting code issues

- [ ] **H: Unit handling.** nbHandrail, nbStairStraight, nbStairSpiral, nbPV, nbPavementPlacer and nbTextureShuffle hardcode mm defaults, minimums and labels. In a metres model the output is 1000× too large, and minimums such as the 500 mm spiral radius become unusable. Only nbTemplate scales correctly (`TemplateBuilder.cs:21`). Add one shared `Units.Mm(doc, value)` helper.
- [ ] **M: Existing layer colours, visibility and locks are overwritten on every bake.** `EnsureLayer` is copied into the Handrail, StairStraight, StairSpiral, PV and Template code. Only set properties when creating a layer.
- [ ] **M: Failed `doc.Layers.Add` returns of -1 are not checked** (Handrail, Stair, PV and Template bakes), and neither are `AddBrep` results. Commands return Success when nothing was added.
- [ ] **M: Duplication.** `EnsureLayer`, `UniqueBlockName`, `CreateLayerAttributes`, the three preview conduits and the stair label and arrow helpers are near-copies. Move them into `Common/` (for example `BakeUtils`, `PreviewConduit<T>`).
- [ ] **L: Shaded previews are drawn in `DrawForeground`.** McNeel samples draw them in `PostDrawObjects`. A `DisplayMaterial` is also allocated every frame.

## 4. Per-command findings

### nbHandrail
- [ ] **H: Undo does not remove the handrail.** The command opens a modeless form and returns Success immediately. Geometry is added later in `OnDialogClosed`, outside any command (`NumbatHandrailCommand.cs:63,166`). Switch to `ShowSemiModal` inside `RunCommand`.
- [ ] **H: The panel frame dropdown labels are swapped.** The dialog offers `["Chamfered","Single Solid"]` (`HandrailDialog.cs:133`), but the generator treats 0 = Solid and 1 = Mitred (`HandrailGenerator.cs:28-29`).
- [ ] M: Exceptions in the Eto handlers are uncaught, and `_activeDoc` stays stale if the document closes while the form is open.
- [ ] M: Post sizes always come from the BoxRail dimensions, even with a round top rail, where those controls are disabled.
- [ ] M: Omitted or reduced panel bays are never reported. `SheetBaysReduced` is never set.
- [ ] M: There is no scripted mode (`-_nbHandrail`).
- [ ] L: Separate swept runs have no corner joins. `IsCurveFlatInZ` and a public overload are dead code.
- [ ] Docs: the README says "from selected curves", but the command picks points to build polyline runs.

### nbPavementPlacer
- [ ] **H: `TryGetPlane` on straight target curves returns an arbitrary plane,** which can be vertical, so pavers can stand on edge (`NumbatPavementPlacerCommand.cs:214,321`). Fall back to WorldXY or the CPlane when the curve is linear.
- [ ] M: A source paver at Z≠0 keeps that offset after orienting (`:269`), because WorldXY is used instead of `paverBox.Center`.
- [ ] L: The paver curve can also be picked as a target. `MaxScalePercent` above 100 can give negative scale. The settings block is duplicated.

### nbTextureShuffle
- [ ] M: `GetOption.Get()` has no loop, so the first option click ends the command. It is still a stub that changes nothing, which the README says.

### nbRandomColour
- [ ] L: Reference and linked layers are counted as changed even when `Modify` fails.

### nbStairStraight / nbStairSpiral / nbStair
- [ ] **H (Straight): switchback stringers bake sloping the wrong way.** Bake groups pieces by bounding-box size and places them by translation only (`StairStraightBake.cs:42-76`), so a mirrored flight reuses the first flight's stringer. Store the full transform, as Spiral does.
- [ ] M (Straight): tread count equals riser count, so the last tread sits at floor level (`StairStraightSolver.cs:20`). Normal practice is risers − 1. Confirm which is intended.
- [ ] L (Spiral): a null `CreateInterpolatedCurve` result reaches `CreatePipe` (`StairSpiralBuilder.cs:480`). The `FrontLips` layer is dead. Guard height is fixed at 1100. Negative skin thickness is allowed.
- [ ] L: `StringersOutward` and `StringerInset` are unused. Changing Width re-centres the stair on the picked line. The Spiral direction arrow is copied from Straight.
- OK: nbStair calls the sub-commands directly (no `RunScript`), conduits are cleaned up in `finally`, and the commands are scriptable.

### nbPV
- [ ] M: Panels always tilt toward world −Y (`PVSolver.cs:236`). That is wrong for the southern hemisphere and ignores the document's north. Add a facing option.
- [ ] M: The parapet margin only shrinks the bounding range, and fit is tested against the un-offset polygon, with corners only in strict mode. Non-rectangular roofs get panels inside the margin.
- [ ] M: Only the single highest upward planar face per object is used, so multi-face pitched roofs get one face.
- [ ] M: The frame width clamp is applied inconsistently (`PVBuilder.cs:33-60`), so a panel can silently disappear.
- [ ] L: The preview duplicates every panel on each option change. Use `PushModelTransform`.

### nbGFA
- [x] **H: Only one bottom face is used** (`NumbatGfaCommand.cs:108-127`). A bottom split into several coplanar faces under-reports area.
- [x] **H: Open or non-solid breps are skipped silently** (`:41`). Filter at selection or report them.
- [x] M: (nbGFA rewrite: one volume = one storey, and nbGFACheck detects overlaps instead.) The containment test uses the bounding-box centre, which fails for L- and U-shaped volumes, and partial overlaps are never detected.
- [ ] M: Custom or None units are not handled. Reuse `ProgramBlocksBuilder.TryGetMetresPerDocumentUnit`.
- [x] L: (nbGFA rewrite) Returns `Result.Cancel` on validation issues. The message box blocks scripted mode.

### nbProgramBlocks
- [ ] M: "1,250" parses as 1.25 m² (`ProgramBlocksData.cs:89`). Detect thousands separators.
- [ ] M: Quoted Excel cells and multi-line cells are not parsed, and "25 m2" suffixes fail.
- [ ] M: The name text has no DimStyle while the area text uses the current one, so the labels can render inconsistently.
- [ ] M: Confirm in Rhino that `Extrusion.Create` extrudes +Z for the plan rectangle (`ProgramBlocksBuilder.cs:217`).
- [ ] L: Reflection is used for `GetCustomUnitSystem`, which is public API. The "Consolas" font is missing on Mac (use `Fonts.Monospace`). Colours beyond 10 categories are random.
- OK: m²→model-unit conversion, unique block names, layer reuse and rollback on failure are all correct.

### nbTemplate
- [ ] M: Existing template layers have their colour, visibility and lock overwritten.
- [ ] L: A failed `Layers.Add` is unchecked. Fixed column widths may overlap long labels.

## 5. What is already good

- The build has zero warnings on both targets.
- Every command uses the passed `doc`, never `RhinoDoc.ActiveDoc`.
- No Windows-only APIs are used, so the code is effectively Mac-ready apart from the Consolas font.
- The release script has good safety checks.
- Folders are organised per command, with a consistent Solver, Builder, Bake and Conduit split.
- The minimum RhinoCommon version, 8.0.23304, means every Rhino 8 service release is supported.
